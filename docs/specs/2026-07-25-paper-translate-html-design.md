# Whole-Paper Bilingual HTML Translation

## Objective

Convert a PDF attachment into a resumable, deterministic bilingual HTML
artifact and import it as a child attachment of the source Zotero item.

The implementation ports the workflow semantics of the original
`paper-translate-html` agent skill into the Zotero runtime. It does not execute
Python or an agent skill at runtime.

## Pipeline

```text
Zotero item/PDF
  → SourceResolver
  → MinerUParser | ZoteroFulltextParser
  → PaperDocument
  → paper-specific glossary
  → batched LLM translation
  → deterministic validation
  → self-contained HTML renderer
  → Zotero.Attachments.importFromFile
```

`PaperDocument` is the single source of truth. Models may only fill a block's
`translation` field. Source text, references, IDs, types, and assets are never
regenerated by a model.

The original skill's TSV glossary is bundled as a read-only candidate
dictionary. Only terms found in the current paper are considered; Zotero
library glossary entries override built-in entries before the model generates
the short paper-specific glossary.

## Storage

Jobs are stored below:

```text
<Zotero Profile>/context-translate/paper-jobs/<job-id>/
├── job.json
├── document.json
├── assets/
└── <paper>（双语）.html
```

The HTML artifact is imported into Zotero storage after validation. The job
directory remains as a restart-safe checkpoint.

## Parsers

### MinerU

The plugin implements the MinerU v4 browser-compatible protocol directly:

1. Request a presigned upload URL from `/file-urls/batch`.
2. Upload PDF bytes with `PUT`.
3. Poll `/extract-results/batch/{batch_id}`.
4. Download and unpack the result ZIP with `fflate`.
5. Store extracted images in the job's `assets` directory.

### Zotero full text

The fallback indexes the attachment with `Zotero.Fulltext`, reads the full-text
cache, and builds a text-only `PaperDocument`. It is appropriate when the user
does not want to upload the PDF.

## Translation protocol

Translatable blocks are grouped by character and block limits. The model
returns only:

```text
@@b0001
translated text

@@b0002
translated text
```

Citations, URLs, DOI strings, inline code, and formulas are replaced by
protected tokens before translation. A block is rejected and retried if any
protected token is missing.

Completed batches update `document.json` immediately. Failed batches are
retried and remaining missing blocks receive an individual repair request.

## Validation

Rendering is blocked when:

- a block ID is duplicated;
- a translatable block has no translation;
- a protected placeholder remains unresolved;
- an image block has no extracted asset.

References and source text never pass through the translation model.

## Zotero integration

Menus are registered through Zotero 8 `MenuManager` for:

- `main/library/item`;
- `main/tab` for PDF reader tabs;
- `main/menubar/tools` for the job list.

The final artifact is imported with `contentType: "text/html"`,
`charset: "utf-8"`, and the bibliographic item's ID as `parentItemID`.

## Unified workbench

The Zotero Tools menu opens a single main-window workbench with two tabs:

- reading translation history across user and group libraries;
- whole-paper jobs with pipeline stages, live progress, usage, errors, and
  lifecycle actions.

Paused and failed jobs persist their last active stage. Resume first persists a
visible queued/restoring state, then continues from `document.json`; action
errors are shown to the user instead of being discarded by a fire-and-forget
promise.
